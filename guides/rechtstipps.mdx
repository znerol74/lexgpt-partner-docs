---
title: "Rechtstipp erstellen & verwalten"
description: "Thema → recherchierter, verlinkter Artikel — gespeichert, mit id fürs Feedback."
---

`POST /rechtstipps` erzeugt aus einem Thema einen recherchierten,
SEO-tauglichen Artikel (österreichisches oder Schweizer Recht, je nach `land`),
**speichert** ihn im Verlauf des Anwalts und gibt ihn inklusive **`id`** zurück. Diese `id` verwendest du beim
[Feedback](/guides/feedback) als `target_id` — mehr musst du nicht mitschicken.

<Note>
  **Auth:** Der Tipp-Lebenszyklus läuft pro eingeloggtem Anwalt und erfordert
  dessen **finditoo-WP-JWT**. Ein reiner Service-Key wird hier mit `403`
  abgewiesen. Siehe [Authentifizierung](/authentication).
</Note>

## Erstellen

Minimal genügt `topic` + `land` — `filters` weglassen, dann greift der
Land-Default:

```bash
curl -X POST https://dashboard.lex-gpt.ai/api/rechtstipps \
  -H "Authorization: Bearer $ANWALT_WP_JWT" \
  -H "Content-Type: application/json" \
  -d '{ "topic": "Kündigungsfristen im Mietrecht", "kind": "rechtstipp", "land": "AT" }'
```

<Warning>
  Recherche + Generierung dauern **~1 Minute**. Setze das Client-Timeout
  entsprechend großzügig (≥ 120 s).
</Warning>

Jede Erstellung zählt als eine Anfrage ins [Kontingent](#kontingent) des
Anwalts.

## Parameter

| Feld | Typ | Default | Beschreibung |
| --- | --- | --- | --- |
| `topic` | string | — | **Pflicht.** Thema/Fragestellung. |
| `kind` | `rechtstipp` \| `blog` | `rechtstipp` | Kurz (Endkunden) vs. länger (Fachpublikum). |
| `stichpunkte` | string (max. 1500) | — | Optionale Stichpunkte, die der Artikel berücksichtigen soll (Unterthemen, Zielgruppe, Pflicht-Aspekte). Steuern die Schwerpunkte; rechtliche Aussagen bleiben an die Recherche gebunden. |
| `land` | `AT` \| `DE` \| `CH` | `AT` | Rechtsordnung + Wording. Verfügbar: **AT** und **CH**. |
| `filters` | FilterConfig | Land-Default | Retrieval-Scope. Weglassen → Land-Default. |
| `as_of` | date | — | Stichtag (YYYY-MM-DD). **Derzeit pausiert** — wird ignoriert, Antwort enthält dann `stichtag_hinweis`. |

<Warning>
  `land` steuert Formulierung und Rechtsordnung, **nicht** die
  Retrieval-Jurisdiktion — die kommt aus `filters.geographic`. Für AT passen
  Land-Default und `geographic: ["bundesrecht"]` zusammen.
</Warning>

## Länder

Verfügbar sind **AT** und **CH**. `land: "DE"` liefert `400`:

```json
{ "detail": "Land 'DE' ist noch nicht freigeschaltet. Aktuell verfügbar: AT, CH." }
```

ISO-Codes werden bevorzugt; Alt-Freitext (`"Österreich"`, `"Schweiz"`) wird
toleriert und normalisiert.

<Note>
  Für **CH** ist die automatische Quellen-**Verlinkung** noch in Arbeit: die
  `[Art. …]`-Marker bleiben derzeit überwiegend unverlinkt (`matched: false`) —
  Recherche, Artikel und `sources` funktionieren voll. Details:
  [Paragraphen verlinken](/guides/citations-links).
</Note>

## Default-Filter pro Land

Lässt du `filters` weg, verwendet der Server den Land-Default:

<CodeGroup>

```json AT
{
  "geographic": ["bundesrecht"],
  "legislation": true,
  "judikatur": true,
  "courts": [],
  "germanCourts": [],
  "swissCantons": [],
  "eurlex": true,
  "documentTypes": []
}
```

```json CH
{
  "geographic": ["ch"],
  "legislation": true,
  "judikatur": true,
  "courts": [],
  "germanCourts": [],
  "swissCantons": [],
  "eurlex": false,
  "documentTypes": []
}
```

</CodeGroup>

Du kannst den Block voll überschreiben — die möglichen Werte liefert
[`GET /rechtstipp/options`](/guides/options). Für die Schweiz kannst du
zusätzlich zum Bundesrecht kantonales Recht einbeziehen:
`"swissCantons": ["ZH", "BE"]` (2-Buchstaben-Codes aus den Optionen).

## Antwort

Die Erstellen-Response enthält den kompletten Artikel in allen Varianten — plus
`id` und `created_at`:

| Feld | Beschreibung |
| --- | --- |
| `id` | **Tipp-ID** → beim Feedback als `target_id`. |
| `created_at` | Zeitstempel. |
| `title` | Generierte H1. |
| `markdown` | Artikel **mit** `[§ …]`-Markern. |
| `markdown_clean` | Artikel **ohne** Marker (Veröffentlichung/Kopieren). |
| `markdown_linked` | Artikel mit Paragraphen als `[Label](URL)`. → [Links](/guides/citations-links) |
| `markdown_tokenized` + `citations` | Marker als `{{CITATION_n}}` + Auflösungs-Map (granulare Integration). |
| `html` / `html_linked` | Minimal-HTML (marker-frei / mit Links). |
| `word_count` | Wortzahl (marker-frei gezählt). |
| `sources` | Recherche-Quellen (inkl. `html_url`). |
| `unbelegte_geschaeftszahlen` | Warnung: Geschäftszahlen im Artikel ohne Beleg in den Quellen. Leer = alles belegt. |
| `pruefhinweise` | Offene Punkte der Prüfliste der Rechtsordnung (siehe unten). Leer = nichts offen. |

<Note>
  Für **verlinkte Paragraphen** ist `markdown_linked` der einfachste Weg — einfach
  statt `markdown` durchreichen. Details: [Paragraphen verlinken](/guides/citations-links).
</Note>

## Genannte Entscheidungen

Nennt `topic` oder `stichpunkte` eine Entscheidung über ihre Geschäftszahl
(z. B. „OGH 7 Ob 81/26a“, „VwGH Ra 2024/01/0123“), holt LexGPT ihren Volltext
aus dem RIS. Findet sich die Entscheidung dort nicht, entsteht **kein Artikel**:
Die Antwort ist `422` mit einem Code, nichts wird gespeichert und keine Anfrage
gezählt.

```json
{
  "detail": {
    "code": "entscheidung_nicht_gefunden",
    "message": "Die Entscheidung 7Ob81/26a wurde im RIS nicht gefunden. …",
    "geschaeftszahlen": ["7Ob81/26a"]
  }
}
```

Nennt die Eingabe mehr als drei Entscheidungen, lädt LexGPT nur die ersten drei.
Für die übrigen kommt `422` mit dem Code `zu_viele_entscheidungen`, auch dann
entsteht kein Artikel. Das heißt nicht, dass es diese Entscheidungen nicht gibt.
Mit weniger genannten Entscheidungen erneut senden.

```json
{
  "detail": {
    "code": "zu_viele_entscheidungen",
    "message": "Je Anfrage werden höchstens 3 genannte Entscheidungen geladen. …",
    "geschaeftszahlen": ["4Ob1/24b"]
  }
}
```

Ist das RIS gerade nicht erreichbar, kommt `503` mit dem Code
`ris_nicht_erreichbar`. Das heißt nicht, dass es die Entscheidung nicht gibt.
Auch dann entsteht kein Artikel. Ein späterer Versuch kann gelingen.

```json
{
  "detail": {
    "code": "ris_nicht_erreichbar",
    "message": "Die Entscheidung 7Ob81/26a konnte gerade nicht aus dem RIS geladen werden. …",
    "geschaeftszahlen": ["7Ob81/26a"]
  }
}
```

Zeige `detail.message` dem Nutzer an. Erstgerichtliche Aktenzeichen wie
„17 C 66/26g“ lösen diese Prüfung nicht aus.

Kommen im fertigen Artikel Geschäftszahlen vor, die keine Quelle belegt, stehen
sie in `unbelegte_geschaeftszahlen`. Der Text bleibt unverändert.

## Prüfliste der Rechtsordnung

Jeder Artikel läuft vor der Auslieferung durch eine Prüfliste seiner
Rechtsordnung (AT, CH). Begriffe einer anderen Rechtsordnung werden
automatisch ersetzt, etwa „Fachanwalt“ in AT oder „ß“ in CH. Überholtes oder
deutsches Recht (etwa eine Erbschaftssteuer in Österreich) bessert LexGPT
gezielt nach. Was danach noch auffällt, steht in `pruefhinweise`:

```json
"pruefhinweise": [
  {
    "kennung": "erbschaftssteuer",
    "art": "rechtslage",
    "hinweis": "In Österreich gibt es seit 1. August 2008 keine Erbschafts- und Schenkungssteuer mehr. …",
    "fundstelle": "Für die Erbschaftssteuer ist das Finanzamt zuständig."
  }
]
```

`art` ist `rechtslage` (überholte oder ausländische Rechtslage), `begriff`
(Begriff, der sich an dieser Stelle nicht automatisch ersetzen ließ), `form`
(Text an der Längengrenze gekürzt, `fundstelle` leer) oder `beleg` (der Artikel
zitiert eine Norm, die nicht aus der Recherche stammt, Kennung
`norm_ohne_quelle`, derzeit nur für Österreich). Liegt die Norm im Bestand,
hängt LexGPT ihren Gesetzestext als Quelle mit `nachgeladen: true` an. Der Text selbst
bleibt unverändert, die Hinweise sind zum Prüfen vor der Veröffentlichung.
`GET` und `PATCH` berechnen sie gegen den aktuellen Text neu, auch
`/refine` liefert sie für den überarbeiteten Text.

## Kontingent

Jede Recherche ist eine Anfrage, im LexGPT-Dashboard wie über diese API. Das
Kontingent eines Anwalts umfasst **100 Anfragen je Kalendermonat** und gilt für
beide Wege gemeinsam. Über die API zählen:

| Aufruf | Zählt |
| --- | --- |
| `POST /rechtstipps` | eine Anfrage je erstelltem Artikel |
| `POST /rechtstipps/{id}/refine` | nicht, die Überarbeitung recherchiert nicht |
| `GET`, `PATCH`, `DELETE`, `/feedback`, `/rechtstipp/options` | nicht |

Abgelehnte und fehlgeschlagene Aufrufe (`4xx`, `5xx`) zählen nicht. Ist das
Kontingent erschöpft, lehnt `POST /rechtstipps` ab der 101. Anfrage im Monat
mit `402` ab, bevor recherchiert wird. Überarbeiten (`/refine`) bleibt auch
dann möglich:

```json
{
  "detail": {
    "code": "kontingent_erschoepft",
    "message": "Ihr Kontingent von 100 Anfragen für diesen Monat ist aufgebraucht. Es erneuert sich am 01.12.2026. Für weitere Anfragen wenden Sie sich bitte an Finditoo.",
    "erneuert_am": "2026-12-01"
  }
}
```

Zeige `detail.message` dem Nutzer an. `erneuert_am` ist der Tag, ab dem wieder
Anfragen möglich sind (Monatserster, Zeitzone Europe/Vienna).

<Note>
  Nach dem Vertragsende ist das Konto für eine Übergangszeit nur noch für den
  Datenexport im Dashboard offen. Alle `/rechtstipps`-Aufrufe antworten dann
  mit `403` und `detail.code = "konto_nur_export"`, die Meldung nennt den
  letzten Tag. Auch hier `detail.message` anzeigen.
</Note>

## Verwalten (Verlauf)

Alle Tipps gehören dem Anwalt (per WP-JWT); es ist derselbe Verlauf, den das
LexGPT-Dashboard zeigt.

| Aufruf | Zweck |
| --- | --- |
| `GET /rechtstipps?kind=all` | Verlaufsliste (ohne Volltext), neueste zuerst. |
| `GET /rechtstipps/{id}` | Einen Tipp mit Volltext laden. |
| `PATCH /rechtstipps/{id}` | `markdown`/`html`/`title` vor der Veröffentlichung bearbeiten. |
| `POST /rechtstipps/{id}/refine` | Text per KI-Anweisung nachbessern (siehe unten). |
| `DELETE /rechtstipps/{id}` | Tipp löschen. |

## Nachbessern per KI-Anweisung

Sagt der generierte Text nicht zu, muss nicht neu generiert werden:
`POST /rechtstipps/{id}/refine` überarbeitet den **aktuellen** Text nach einer
freien Anweisung — ideal für eine Chat-artige Nachbesserungs-Box im eigenen
Backend.

```json
{ "instruction": "Ergänze ein Unterthema zur Verjährung" }
```

Die Antwort ist der komplette aktualisierte Tipp (gleiches Schema wie `GET`).
Eigenschaften: arbeitet auf dem gespeicherten Markdown weiter (auch nach
`PATCH`-Bearbeitungen), **keine neue Recherche** — Quellen und Zitatmarker
bleiben erhalten; schlägt die Überarbeitung fehl (`502`), bleibt der Text
unverändert. Die Überarbeitung zählt nicht ins
[Kontingent](#kontingent) und ist auch bei erschöpftem Kontingent möglich. Auch
die Überarbeitung läuft durch die
[Prüfliste der Rechtsordnung](#prüfliste-der-rechtsordnung).

<Info>
  `GET`/`PATCH` liefern dieselben Textfassungen wie die Erstellen-Antwort:
  `markdown`, `markdown_clean`, `markdown_linked`, `html`, `html_linked`, dazu
  die **persistierten** `markdown_tokenized` + `citations`. Nach einem `PATCH`
  mit neuem `markdown` sind alle frisch gegen die gespeicherten Quellen
  aufgelöst. Bearbeitest du einen Tipp per `PATCH`, bleibt das
  Original der Generierung intern erhalten (für die Feedback-Diagnose).
</Info>
